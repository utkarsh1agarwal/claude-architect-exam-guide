## Part 1: Questions 1–35

**Q1. Answer: B** *(D1)* — Two constraints bind: tools must run inside the network (no inbound port), and the team will not run agent-loop or session-history infrastructure. Managed Agents with a **self-hosted sandbox** meets both: Anthropic hosts the loop and session history, and tool execution happens on sandbox workers the team runs inside the network. The honest trade-off is operating those workers. A fails because the MCP connector needs a publicly reachable HTTP server, which the no-inbound rule forbids, and "gives up nothing" is a red flag; C meets the network rule but breaks the charter note, because the team would own session persistence and the loop; D also makes the team own the loop, and per-sheet stateless calls lose the cross-sheet state a multi-hour transmittal review needs.

**Q2. Answer: D** *(D3)* — Sum the trace: 1.4 + (1.8 + 2.1 + 1.2 + 0.9) + 2.2 = **9.6 s**. The four independent tool calls take 6.0 s, the largest block. If the model requests them in one turn and the app runs them concurrently, that block shrinks to the slowest call (2.1 s), giving **5.7 s**, under target with no model change. A attacks the smaller block (3.6 s of model time) and risks the quality floor, which is already tight; B improves time to first token, but the target is for a **complete** answer; C does nothing useful because cache reads are already near 100%, and caching only shortens pre-first-token time, not tool time.

**Q3. Answer: A** *(D4)* — Budget = cases × configs × trials: 300 × 2 × 5 = **3,000**. Running both versions on the **same** cases with repeated trials lets you average out run-to-run variance (which is as large as the observed 2.4-point swing) and compare per case, so case mix cannot explain the difference. B resamples the same 300 cases with one trial each, which adds no information about run-to-run variance and fakes a larger sample; C gives each version different cases, so case mix is confounded with the prompt effect; D needs 300 × 2 × 8 = **4,800** runs, over the approved budget.

**Q4. Answer: C** *(D2)* — The errors cluster on one pattern because the prompt never states the firm's rule; the model is faithfully applying the broad rule it was given. Stating the rule plus its reason is a zero-shot fix that costs a few dozen tokens and gives the model what a capable new reviewer would need. A adds thousands of tokens spread evenly across document types, so few examples target the failing pattern; B changes how much the model reasons, not what rule it knows, so more thinking applies the same wrong rule at higher cost; D changes output shape, but structured outputs already guarantee a valid label, and a wrong value is still a valid enum value, so the ambiguity just moves to a new bucket.

**Q5. Answer: B** *(D5)* — The misuse path is a model being talked into a refund that the fare rules forbid. **Q6. Answer: A** *(D3)* — Least privilege means removing capability the agent does not need. Disabling the toolset by default and enabling only the three read tools removes the 43 unused tools, and a read-only credential means even a misrouted call cannot write. **Q7. Answer: D** *(D1)* — Capacity: 3 officers × 50 × 5 = **750** reviews a week. Discretionary plus denial cases = 30% of 2,400 = **720**, which fits. Completeness checks and document requests are reversible and low-stakes, so Claude can own them; discretionary and denial decisions are accountable and, for denials, start a legal clock, so a named officer decides them with Claude drafting. **Q8. Answer: C** *(D7)* — Agent SDK permission order: **hooks → deny rules → ask rules → permission mode → allow rules → `canUseTool`**. A hook `allow` does not skip the deny and ask steps. No deny rule matches, then the ask rule `Bash(git push:*)` matches, and an explicit ask-rule match falls through to `canUseTool` even in `bypassPermissions`. So the release-channel callback decides. **Q9. Answer: A** *(D4)* — The evidence points to **verbosity bias**: new synopses are more than twice as long, the judge rewards them, and blind humans see no difference. **Q10. Answer: A, D** *(D5)* — Finding 1 is indirect prompt injection with a high-impact tool in reach. **Q11. Answer: B** *(D3)* — Accuracy fell as the catalog grew, so the problem is choice overload in the context, not cost. **Q12. Answer: B** *(D1)* — Work out each limit. Input: cache reads don't count here, so 2,000 counted tokens per job → 2,000,000 / 2,000 = **1,000 jobs/min**. **Q13. Answer: D** *(D2)* — Compare **cost per completed task**, not price per call. Total = price + (error rate × $1.20). Smallest: 0.004 + 0.22 × 1.20 = **$0.268**. **Q14. Answer: C** *(D6)* — 2 of 400 is a measured **0.5%** leak rate, so "prevents" and "none" overstate the evidence. **Q15. Answer: A** *(D3)* — Retries multiply across layers: 3 (SDK: 1 + 2 retries) × 3 (wrapper) × 4 (queue) = **36** attempts per job, so 1,200 × 36 = **43,200** requests during an overload. B is right practice for a side-effecting step, but the failures happen before the write, so duplicates are not the problem; C multiplies the same storm onto a second model; D treats a provider overload event as a rate-limit problem and leaves 36× amplification in place.
