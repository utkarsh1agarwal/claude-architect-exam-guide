**Q3. Answer: A** *(D5)* — The harm is exfiltration through a write tool that can reach any address. **Q4. Answer: C** *(D4)* — Budget check: 240 cases × 2 configurations × 4 trials = 1,920 runs, which fits 2,000. **Q5. Answer: A** *(D2)* — Apply the floor first, then cost per completed task including correction cost. **Q10. Answer: A** *(D3)* — The binding constraint is accuracy, and the failing stage is the top-k cut, since the gold passage usually sits at rank 9–18. **Q11. Answer: C** *(D6)* — A good ADR states what was measured, does not over-claim, and records how the stakeholder's constraint is enforced. **Q12. Answer: B** *(D1)* — The steps are fixed, known and ordered, so the least dynamic pattern, a prompt chain, fits. **Q13. Answer: D** *(D2)* — A cache hit needs an identical prefix up to the breakpoint, in the order tools → system → messages. **Q14. Answer: C** *(D3)* — Retries multiply across layers: 3 × 4 × 6 = 72 attempts per job, which is exactly what the log shows, and it deepens the overload. ## Part 2: Questions 36–70


**Q36. Answer: B** *(D2)* — The facts are right and the style is inconsistent. That is the classic case for few-shot prompting: three to five diverse examples in `<example>` tags show the house style across match types, so the model generalizes the pattern rather than copying one report. The cost is a few thousand stable tokens, which can be cached. **A** constrains the shape of the output, not prose style or tone, and readers are people, not parsers. **C** spends extra output tokens on planning, but the model is not missing reasoning; it is missing a concrete picture of the target style. **D** uses a single example, which leads to over-imitation: every report would copy that one match's length and incidental details, whether it was a cup final or a friendly.

**Q37. Answer: D** *(D3)* — Locate the failing stage first. Recall@100 (66%) is barely above recall@20 (64%), so the gold chunk never enters the candidate set. The reranker and the `k` cut-off are not the problem; first-stage retrieval is. Exact identifiers like `HV-44817-B` are what embeddings match poorly and lexical search (BM25) matches well, and context-free table fragments embed badly. Hybrid search plus contextual chunk prefixes (contextual retrieval) fixes the stage that fails, and re-measuring recall@100 confirms it. **A** and **B** widen later stages, which cannot surface chunks that were never retrieved. **C** is the scale-up reflex; no model can cite a catalog row it never sees. (Compare Q10, where the gold passage was retrieved but ranked just below the cut-off.)

**Q38. Answer: A** *(D4)* — Derive the success criterion from the business outcome: a correct reservation and a correct charge in the PMS. For a state-changing agent, that means grading final environment state with code checks, in a sandbox reset before every trial, on cases sampled to match the deployed distribution, including hard cases such as sold-out dates and rate changes. **B** grades the agent's own confirmation, which is a self-report; a transcript can say "updated" when the PMS is wrong. **C** turns every regression into a guest-facing incident and gives no pre-release gate. **D** grades the process rather than the outcome and fails valid alternative paths, such as checking availability before modifying.

**Q39. Answer: B** *(D1)* — This is the twin of Q7, and one detail flips the answer: ZDR is not required here. **Q40. Answer: C** *(D5)* — The injection surface is a third-party Skill that pulls instructions from an external URL at runtime. **Q46. Answer: D** *(D6)* — Look for what the platform does not enforce. Managed Agents permission policies cover the built-in agent toolset and MCP toolsets, not custom tools. That makes `quarantine_mailbox`, a disruptive action, the one capability with no documented owner or approval control. Without a runbook entry naming who owns it, how calls are approved and how a wrong quarantine is reversed, the SOC team cannot operate the deployment safely. **A** is useful context but does not block operation. **B** documents a flow Anthropic runs for `mcp_oauth` vault credentials. **C** is convenient but does not block anything.

**Q47. Answer: A** *(D5)* — This is the twin of Q9, flipped by one detail: the action is reversible until checkout, and waiting causes harm (repeat stays fall when resolution is slow). When an action is cheap to reverse and delay hurts, let the agent act and have a named human review every action within the reversal window. At 200 credits a day against 240 reviews of capacity, review before checkout is feasible. **B** fits capacity on paper, but the 50-minute queue breaks the 15-minute resolution that drives retention. **C** gates on the agent's self-assessed risk. **D** has no review before refunds post, and a 5% month-end audit finds errors only after they become refunds.

**Q48. Answer: D** *(D4)* — Two factors changed at once, so the 9-point gain is confounded. The decision is narrower than "which factor matters": the new prompt ships anyway, so the question is whether the balanced tier adds value on top of it. Running the new prompt on the smallest tier (150 × 3 = 450 runs, within the 600 left) gives exactly that comparison, case by case on the same cases, with only the tier differing. **A** spends 750 runs (over budget) to sharpen a confounded number. **B** confounds each factor with a different half of the cases. **C** is the textbook full 2×2, but it needs 900 runs, and its extra cell (old prompt on balanced) answers a question nobody is deciding.

**Q49. Answer: C** *(D1)* — Evaluate the architecture under the stated trust condition, not under load (which already passed). The weak point is that the model, which reads attacker-controlled input, chooses the value that scopes data access. A malicious tenant can prompt the agent into passing another tenant's ID, and the metadata filter will apply it faithfully. Isolation must come from the authenticated session on the server: the tool takes no tenant argument, and the server applies the filter (ideally backed by per-tenant partitions or credentials). **A** is a load concern, and the stem says load tests passed. **B** answers a different question (redaction) and would not stop cross-tenant retrieval. **D** is an instruction-level change; tags do not make a model-chosen value trustworthy.

**Q50. Answer: B** *(D3)* — The failure pattern is a side-effecting call that succeeded but timed out before confirming, followed by a blind retry. The reliability control is idempotency: one key per transfer intent, persisted with the step and sent on every attempt, so the gateway recognizes a repeat and returns the original result. Retries stay safe, and slow transfers still complete. **A** reduces how often this happens, but any call slower than 90 seconds still duplicates. **C** pushes the retry onto the customer, who can double-send just the same, and it degrades service. **D** relies on the model to check, and it races against a transfer the gateway has not yet recorded.

**Q51. Answer: A** *(D7)* — Split what teams may change from what must be enforced centrally. The command, subagent and MCP config go in a plugin on an internal marketplace that teams can extend. The safety hook goes in managed settings (for example a managed hook, with `allowManagedHooksOnly` if needed), which teams cannot override, and which applies in headless runs without depending on a plugin installing in time. **B** fails because subagents loaded from plugins ignore frontmatter `hooks`, so the safety hook would silently never run. **C** over-corrects: full lockdown blocks the customization teams need. **D** relies on a request, and any team can delete the hook.

**Q52. Answer: C** *(D2)* — When every tier fails the same cases, the cause is missing information, not capability. The facts live in notes the prompt never includes. Bring the relevant notes into context, re-run the eval, then pick the cheapest tier that clears the 90% floor. **A** is the scale-up reflex: a two-point difference between tiers that all sit far below the floor, and more trials cannot supply missing facts. **B** changes how much the model reasons, not what it knows. **D** shows what a good explanation looks like, but the model still lacks the facts needed to write one.

**Q53. Answer: B, D** *(D3)* — Finding 1 is a per-session outlier: 0.6% of sessions looping is invisible in medians and aggregates. Per-session tool-call and token counts with outlier alerts, plus a hard cap, surface and contain it (**B**). Finding 2 is a failure inside an app-run custom tool. API-side tracing covers model requests and API-run tools, not client tools, and the wrapper hides the error as an empty result. Instrument the tool itself, alert on per-dependency errors and empty results, and return an explicit error (**D**). **A** is aggregate and lagging; it showed the 38% rise but not the cause. **C** samples more of a layer that has no spans for the client tool and does not single out per-session outliers.

**Q54. Answer: B** *(D5)* — Rank by exposure after existing controls, weighted by evidence. R3 has no control, has already happened, and spreads beyond this agent: it exhausted shared quota and broke a production system in another department. R1 is limited by read-only tools and human review of advisory answers. R4 is caught by technicians checking each cited chunk against the manual. R2's supply-chain risk is controlled by pinning a reviewed hash. **A** puts a heavily controlled risk above the one that already caused an outage. **C** ranks the verified-answer risk above injection, and **D** ranks the pinned server highest, the reverse of its residual exposure.

**Q55. Answer: A** *(D4)* — Isolate by elimination. Retrieval returned the right content, the prompt was reviewed, and tools succeeded, so retrieval, prompt and tool errors are ruled out. The identical request succeeds 19 of 20 times on the larger tier but 6 of 20 on the smaller one, and only for the harder multi-account question type. That is a capability mismatch. Route that query type to the capable tier and keep the cheap tier where it works. **B** contradicts the trace, which shows the correct passage was retrieved. **C** treats a reasoning failure as invented facts; the inputs were right, and quoting them does not fix the reasoning. **D** is untested: one example is unlikely to close a 6-versus-19 gap that the larger tier closes on its own.

**Q56. Answer: D** *(D1)* — Two stated constraints decide it. The categories interfere when tuned together and have separate owners, and tool reachability must differ by category (concierge must never reach payments). Routing fits both. A classifier call labels the request (Claude decides the label), and code dispatches it to a dedicated prompt and tool set (code decides which tools are attached). **A** fails the security requirement: Skills change the instructions loaded, not which tools are attached, so the single agent can still reach payments. **B** adds runtime decomposition that a known set of categories does not need. **C** improves quality iteratively but separates neither prompts nor tools.

**Q57. Answer: A** *(D6)* — A good revision states measured behavior (1.4% unsupported factors) instead of "accurate", adds a deterministic control (cited factors checked against the record in code before display), meets the reproducibility constraint by storing each issued explanation, and records the residual risk honestly. **B** fails reproducibility: outputs are not deterministic, so a regenerated explanation may differ from what the customer actually saw. **C** claims no risk on the basis of an unreleased model, which overstates certainty. **D** detects problems a month later on a small sample and still stores nothing a customer could contest.

**Q58. Answer: B** *(D2)* — Allocate effort per workload against evidence. Classification shows parity (99.2% vs 99.1%), and `low` brings p95 from 5.1 s to 2.4 s, under the 3 s budget. The investigation agent is accuracy-first with long sessions, so it keeps `high` effort, and context editing clears consumed tool results to keep its context healthy over 2 hours. **A** applies classification evidence to a different, accuracy-critical workload that has no such eval. **C** breaks the real-time gate requirement, since Batches is asynchronous. **D** improves time to first token, but a gate system needs the complete label, so p95 to completion is unchanged.

**Q59. Answer: C** *(D3)* — Identify the binding constraint: precision (86% is below the 90% floor). Then check the others. The capable tier reaches 92%; 2.5 h × 1.8 = 4.5 h fits the 8-hour window; $1,800 fits the $2,000 budget. That relieves the binding constraint at the least cost to the others. **A** breaks the budget ($2,700) with an unproven gain, since voting reduces variance rather than raising capability. **B** fixes a constraint that is not binding (time) and leaves precision at 86%. **D** pays for speed the job does not need and breaks the budget ($3,600).

**Q60. Answer: D** *(D4)* — Locate where time and spend concentrate. Output generation dominates: 1,150 tokens ÷ 130 per second ≈ 8.8 s of the 9.4 s, and output is 78% of spend. A shorter format, already shown in blind review to be equally helpful and then validated on the quality eval, cuts both: about 0.8 + 400/130 ≈ 3.9 s, under the 6 s timeout, with roughly 65% less output. **A** works on the input side, which is already 94% cached; caching affects time to first token, not generation time. **B** improves time to first token, but the app shows nothing until the answer is complete. **C** is a hard ceiling that truncates answers mid-sentence rather than making them concise.

**Q61. Answer: C** *(D5)* — Map the obligation to its control property. "Must not be sent to any AI provider" concerns what the model sees, which is redaction. Detecting and redacting personal fields and names in the narrative before the request, with placeholders re-mapped only inside the foundation, keeps the data off the wire. Logging the redaction results gives auditors their evidence. The narrative the task needs is kept. **A** controls where processing happens, not whether data is sent. **B** controls how long data is retained, but the data is still sent, which the policy forbids. **D** controls who can call the model; the grants team would still send personal data.

**Q62. Answer: A, C** *(D7)* — Finding 1 is an unbounded headless run. `--max-turns` and `--max-budget-usd` put hard limits on it, and the run ends with an error result subtype that CI can detect and report (**A**). Finding 2 is subagent permission inheritance: when the parent runs in `bypassPermissions`, the subagent inherits that mode and its own `permissionMode` is ignored. The subagent's `tools` list still applies in every mode, so limiting it to read-only tools enforces "read and comment only" (**C**). **B** is an instruction the agent may never act on in a loop. **D** changes the same field that is already being overridden by the parent's mode, so it changes nothing.

**Q63. Answer: B** *(D1)* — Apply the ceilings first. Y breaks both (p95 75 s, $16,000). W breaks the 60-second reply requirement, since replies arrive the next morning. X and Z meet both. Between them, X delivers far more of the business metric (+6.0% vs +2.0%). The honest trade-off is the 1.5 points of lift X gives up compared with Y, which cannot be had within the ceilings. **A** treats a hard SLA as optional. **C** optimizes cost, which is a ceiling, not the objective, and leaves most of the value unclaimed. **D** misstates the trade-off: next-morning replies are not a cost of W but a violation of the 60-second ceiling.

**Q64. Answer: D** *(D3)* — This is a confused-deputy problem. The assistant acts with a shared identity more powerful than the user, so any user can borrow its access. The fix is to act as the user: pass the user's delegated OAuth token so the document store enforces its own permissions, and remove the service account's domain-wide reach. **A** addresses credential exposure, a different risk; a rotated key is just as over-privileged. **B** asks the model to enforce entitlements it cannot see, and job titles are not permissions. **C** detects the leak after the memo has already been shown.

**Q65. Answer: A** *(D2)* — Two problems: accuracy is below the floor, and reasoning leaks through malformed tags. Native adaptive thinking keeps reasoning out of the response text, which removes the leak, and it lifts accuracy. The lowest effort level that clears the 88% floor (`low`, 88.5%) avoids unnecessary tokens. A structured-output schema delivers the verdict in a parseable form. **B** may reduce tag errors but keeps reasoning in the customer-visible text and leaves accuracy at 81%. **C** cuts tokens but drops reasoning that the task measurably needs. **D** spends maximum tokens twice over for accuracy the floor does not require.

**Q66. Answer: B** *(D5)* — Untrusted résumé text sits in the same channel as the recruiter's instructions, and the agent holds a write tool, so injected text becomes an action. The architectural control separates reading from acting. A step with no write tools reads the résumé and returns only code-validated fixed fields (such as skills and years of experience), which free text cannot turn into commands. Stage changes come only from recruiters, who still move candidates quickly. **A** is probabilistic and also penalizes candidates on the basis of a classifier's guess. **C** is an instruction that untrusted text can override. **D** detects after a candidate has already been advanced.

**Q67. Answer: C** *(D4)* — This is the twin of Q32, and the evidence flips the response. Here reviewers confirmed that the new behavior is wrong (speculative injury claims), and the cause is an over-emphatic, absolute prompt line that newer models follow literally. Fix the prompt with plain conditional wording, rerun the full suite, and migrate before retirement. **A** is impossible: pinning does not survive retirement in 60 days. **B** writes a confirmed regression into the baseline. **D** treats a systematic, explained cause as noise; more trials will reproduce the same speculative claims.

**Q68. Answer: A** *(D1)* — An audit record must come from the runtime, not from the agent's own account of what it did. Tool hooks (Pre/PostToolUse) or trace spans that carry the subagent's ID and type record every query that actually ran, including the two the subagents left out. Storing each brief with its result supports reproducible reruns. **B** makes the self-report tidier but no more complete. **C** proves the self-report was not altered, not that it was complete. **D** asks a second model to check the first model's self-report, with no access to what actually ran.

**Q69. Answer: D** *(D7)* — Two separate causes match the evidence. Subagents loaded from a plugin ignore frontmatter `hooks`, `mcpServers` and `permissionMode` for security reasons, which is why the hook and tools are missing even in interactive runs. They belong in the plugin's `hooks/hooks.json` and its MCP configuration. Separately, headless runs install plugins in the background, so components can be missing on the first turn; `CLAUDE_CODE_SYNC_PLUGIN_INSTALL=1` makes CI wait for installation. **A** changes the install scope, not how plugin subagent frontmatter is treated. **B** turns an enforced control into an instruction. **C** controls where plugins come from, not when or how their components load.

**Q70. Answer: C** *(D6)* — Batches cannot back a 5-minute commitment, because results can take up to 24 hours. But the discovery notes show the real need is narrower. Splitting by cargo class puts perishables (15%, within the 20% the budget can cover) on real-time calls that can meet minutes, keeps the rest on cheaper Batches, and rewrites the clause so each class has a commitment the architecture can keep. **A** gives up a real business need that the architecture can meet. **B** still depends on Batches timing, which has no minute-level guarantee. **D** pays real-time prices for 85% of volume that does not need them, exceeding the budget.
