## Part 1: Questions 1–35

**Q1. Answer: B** *(D1)* — The binding constraint is custody: all traffic must stay in the bank's AWS account under the **Bedrock** agreement. Claude Managed Agents is not offered on Amazon Bedrock, so the fit is the **self-hosted Agent SDK** pointed at Bedrock, and the honest trade-off is that the bank now owns session storage, sandboxing, and the loop. A fails because a self-hosted sandbox still runs on Anthropic's hosted Managed Agents service, outside the Bedrock agreement. C answers a location question (`inference_geo`) and still leaves Bedrock. D also leaves Bedrock for the first-party API, and a stateless loop does not give the long-running, sandboxed runtime the team asked for.

**Q2. Answer: D** *(D3)* — The deciding evidence is that the **first call succeeded** at the payments service and only the response timed out, so the retry re-ran a side effect. An **idempotency key** derived from the order and refund reason lets the payments service return the original result for the repeat. Legitimate retries still work, and duplicates cannot happen. A drops legitimate retries and sends every slowdown to humans. B is an instruction, not enforcement: the agent cannot see a refund that is still in flight. C lowers how often it happens but does not remove the cause, because any response slower than the new timeout still duplicates.

**Q3. Answer: A** *(D2)* — A cache hit needs the prefix (tools → system → messages, up to the breakpoint) to be identical. A per-request timestamp on **line one** of the system prompt changes the prefix every call, which is exactly why logs show ~9,000 `cache_creation_input_tokens` and 0 `cache_read_input_tokens`. Moving the volatile value **after the breakpoint** (into the user turn) keeps the time information and restores hits. B is right practice for the wrong failure: nothing is expiring, and a 1-hour write costs more. C's extra breakpoint still includes the changing first line. D helps only for requests in the same minute, and most requests still miss.

**Q4. Answer: C** *(D4)* — Verdicts that flip to **whichever reply appears first** when the order is swapped are the signature of **position bias**. The fix is to judge both orders and count only consistent wins (or randomize order and balance it). A fixes verbosity bias, but the stem says lengths are similar. B addresses self-preference, but the judge is already from a different family, and keeping the fixed order keeps the bias. D uses the judge's self-reported confidence, which is not evidence of correctness and leaves the order effect in place.

**Q5. Answer: A, C** *(D3)* — Least privilege means removing what the trace shows is never used and narrowing what is over-broad. **A** removes two never-called tools, including the destructive `delete_tenant_record`, without breaking any workflow. **C** replaces a general read-write SQL tool, used only for one lookup, with a narrow, read-only, fixed-purpose tool that returns only needed fields. B is an instruction, not enforcement: the tools remain callable. D is a partial fix: keyword blocklists are incomplete (other write statements or alternate spellings slip through), and the read-write credential and broad query surface remain.

**Q6. Answer: B** *(D5)* — Gate placement follows **reversibility**. Rebookings are free to change before departure, so they can run without a pause. Compensation **cannot be clawed back**, so a supervisor approves each `issue_compensation` call, enforced in the tool layer where the agent cannot skip it. This removes most of the 900-item queue without exposing the irreversible action. A relies on the model's self-assigned risk score, which is not an enforceable control. C detects after the fact for an action that cannot be undone. D keeps the over-correction of gating everything and only adds capacity, so approval fatigue and delays remain.

**Q7. Answer: A** *(D1)* — The steps are **fixed, known, and ordered**, and a failed check must stop the flow, so the least dynamic pattern is a **prompt chain with code gates**. The delegation boundary is that Claude does the language work (extraction, drafting) and code owns the order and the deterministic policy check. B gives the model control over order and over judging the check, which adds unpredictability with no benefit. C is for subtasks that are unknown until the input is read, which is not the case here. D cannot work, because the policy check and the letter both depend on extraction output, and drafting before the check wastes work.

**Q8. Answer: D** *(D4)* — Run-to-run variance (up to 4 points) is close to the expected effect (5 points), so the design needs **repeated trials on the same cases**. 120 transcripts × 2 prompts × 5 trials = **1,200 runs**, exactly the budget, and per-transcript means remove case-mix differences. A uses a single trial, so variance cannot be separated from the prompt effect. B compares different transcripts for each prompt, which confounds case mix with the prompt. C needs 150 × 2 × 5 = 1,500 runs, over budget, and trimming partway makes the trial count uneven.

**Q9. Answer: C** *(D6)* — No vendor can promise one model version for five years: models are deprecated and retired on Anthropic's schedule, with **at least 60 days' notice**, and outputs are non-deterministic anyway. The supportable commitment is **advance notice plus a regression pass** on an agreed acceptance set before every switch, including forced ones. D is still an unsupportable fixed-duration guarantee.

**Q10. Answer: B** *(D3)* — At about **110,000 tokens**, the handbook is well under the ~200K-token size where Anthropic suggests skipping RAG and putting the whole corpus in the prompt. **Q11. Answer: D** *(D2)* — Treat accuracy and latency as **floors and ceilings**, then pick the cheapest tier that passes both. Only the smallest tier meets 94% (95.1%) **and** p95 under 1.0 s (0.6 s), and it is also the cheapest. A ignores a binding latency requirement; "safety-relevant" does not override a stated SLA. B breaks the 1.0 s limit (1.4 s), and "close" is not "meets". C adds a second call to every report, which raises cost and pushes latency past the limit, to fix an accuracy floor that is already met.

**Q12. **Q41. **Q57. Answer: C** *(D1)* — There are distinct categories with **separate tools and owners**, and a change for one category **hurt another** (a 6-point drop). **Q58. Answer: A** *(D5)* — Rank by **residual exposure after controls**. Chat injection is screened, and the agent has read-only tools (B). Exhaustion is capped (C). **Q59. Answer: C** *(D4)* — Derive the criterion from the **business outcome**: underwriters should decide without reopening the source. **Q60. Answer: B** *(D3)* — This is a **confused deputy**. The assistant acts through a shared account that can read everything, so it gives a manager access the HR system itself would deny her. **Q61. Answer: A** *(D2)* — The errors **cluster** on one **unstated business rule**. **Q63. Answer: A, C** *(D3)* — Each incident hid from **averages and error counts**. **Q65. Answer: D** *(D4)* — Accuracy and groundedness were measured, and latency stayed within the SLA. What **tripled** was spend, driven by 6–9 `search_policy` calls per conversation instead of 2. **Q66. Answer: B** *(D6)* — Zero errors in 200 trials does not show a zero error rate. **Q67. Answer: A** *(D1)* — A procedure shared by many agents, needed **only sometimes**, and governed by one owner is the case for a **Skill**. There is one reviewed version in one place. **Q68. Answer: B** *(D7)* — When the parent runs in `acceptEdits` (or `auto` or `bypassPermissions`), the subagent **inherits** that mode, so its own `permissionMode: "plan"` is ignored. **Q69. Answer: C** *(D3)* — The call is **fixed**, happens on every run, has one consumer, and latency matters. Nothing here needs the model to decide whether to call it. **Q70. Answer: D** *(D1)* — Apply the constraint, then compare the measurable outcome. Proposal 1: 35% × 30% = **10.5%** of total handle time, at p95 **3.2 s**, inside the 4-second limit.
